# Pixiv 收藏分类工具

[English](README.md) · [日本語](README.ja.md) · 简体中文

**从整个收藏夹自动选出一组尽量精简的分类，算清楚覆盖了哪些作品，再沿用这套分类持续整理新增收藏。**

工具从收藏本身的原始标签中选择分类，以覆盖所有可读作品为目标并去除冗余选择；实际写入前，再核对每件作品已有标签和新分类合并后是否超出限额。

**当前版本：0.4.0。** 支持简体中文、日语和英语，默认跟随浏览器语言，也可以手动切换并记住选择。

## 核心功能

- **自动决定“应该建哪些分类”。** 从全收藏的标签与作品对应关系出发，按集合覆盖计算候选分类，再删除冗余选择。无需先手工搭好词典；低频标签如果能覆盖其他分类遗漏的作品，也可以保留。
- **把“有没有漏掉”变成可检查的数字。** 显示按作品去重的覆盖率、未覆盖 PID、单件最多匹配分类数；手动勾选后即时更新。目标是各分类的并集覆盖可读收藏全集，分类之间允许重叠。
- **写入前核对真实容量。** 选集阶段限制单件最多匹配 10 个本地分类；写入前再检查“已有标签 ∪ 新分类”是否超过 Pixiv 的 10 标签上限。超限整件跳过，旧标签保留。
- **追加后确认实际结果。** 总收藏、旧标签、公开状态保留，只追加新分类。先写一件并回读，再处理其余作品，最后重新核对，并保留逐件执行记录。
- **生成一次，持续更新。** 保存规则与分类名称对应关系，之后只补缺少的分配；也可选择将外部已有分类的成员视为已覆盖，再为剩余作品计算补充分类。

核心差异是 **全收藏覆盖规划 → 容量核对 → 回读验证追加 → 保存规则持续更新** 这套流程。自动打标签、保存规则本身已有其他工具提供；在本次核对的三个项目说明中，未见内建“自动选择分类集合、去冗余、显式检查漏项”的完整流程。具体来源与范围见 [同类项目比较](docs/COMPARISON.md)。

当前算法不保证分类数达到全局最少，也不保证任意数据都能 100% 覆盖。已有标签容量在选集后核对，因此预览全覆盖仍可能遇到无法写入的作品；未覆盖与跳过项会明确显示。

## 安装与更新

建议使用支持 Web Locks 的新版桌面 Chrome / Edge 和 [Tampermonkey](https://www.tampermonkey.net/)。按提示允许用户脚本运行及访问 `www.pixiv.net`。

1. 下载 [安装 ZIP](dist/pixiv-bookmark-analyzer-install.zip)，在 Tampermonkey → 管理面板 → 实用工具 → ZIP 导入中安装。
2. 已有版本请更新原有条目，保留脚本数据。若导入没有识别为更新，打开原脚本编辑器，用[新版源码](pixiv-bookmark-analyzer-prototype.user.js)完整替换、保存。
3. 登录自己的 Pixiv，刷新自己的插画收藏页。

脚本基础名称仍是 `Pixiv 收藏参数扫描器 · 只读原型`，用于保持更新身份；管理器可能显示日语或英语名称。0.4.0 已支持点击按钮后实际追加分类。安装不需要编译，也不要在系统文件管理器里双击执行 `.js`。

## 首次分类

1. 填写自己的数字用户 ID，点击 **开始 / 继续**。读取公开及非公开的插画、漫画、动图收藏，不处理小说。
2. 扫描完成后点 **打开分类试用**。自动选集后，可以勾选调整规则、查看对应作品和未覆盖作品。
3. **已有分类要纳入已成集合吗？** 默认不勾选。启用后只把旧分类当前成员计为已覆盖，不猜测自定义名称的含义，不往外部旧分类追加成员。
4. 点 **核对 / 更新主收藏**，读取最新收藏和已有标签，查看可追加、已满足、未处理数量及新分类名称。这一步只读取数据。
5. 点 **开始追加 X 件**。先写入一件并回读确认，再继续处理；完成后核对总收藏、已有标签和公开状态。

运行时保持页面打开，暂时不要在其他页面增删收藏或修改标签、公开状态。完成后自动下载的 `pixiv-classification-project.json` 是分类参数与执行记录备份。

## 更新分类及切换语言

- 新增收藏后，点 **更新分类**，核对预览后再开始追加。保存的规则与分类名称继续使用，已满足的作品不重复写入。
- 新增规则会为旧作品和新作品补充匹配分类。取消规则会停止后续分配，先前生成的分类和成员仍保留。
- 主面板和分类窗口顶部都有 **界面语言**，可选跟随浏览器、简体中文、日本語、English。切换立即生效，未保存的勾选、搜索和当前预览保留。
- 自动模式按浏览器偏好顺序选择首个支持的语言；中文各地区偏好统一显示简体中文，全部不支持时使用英语。
- 语言只影响界面、提示和确认弹窗。原始 tag、分类名称、规则映射、默认 `新_` 前缀、JSON 字段和诊断代码保持不变。

## 分类逻辑和限制

分类由 Pixiv 收藏标签实现。同一作品可以属于多个分类；覆盖率按作品去重，分类件数相加可以大于全集。

总收藏、旧标签和公开状态保留，只追加收藏标签。不可读或异常记录不参与分类，仍留在总收藏。根据 [Pixiv 官方说明](https://www.pixiv.help/hc/ja/articles/235585488)，每件收藏插画最多 10 个收藏标签。已有标签与新分类合并后超过 10 个时，整件作品跳过本轮追加。

自动选择采用精确原始 tag 匹配、优先增加覆盖、随后移除冗余标签，不保证分类数量全局最少。精确 `R-18` 和带数字门槛的 `users入り` 标签默认跳过，手动仍可选。无匹配规则的作品会保留为未覆盖。

更新仍需分页读取收藏列表核对当前情况；增量指仅写入缺少的分类。网络错误、无法确认响应或限流时会暂停，不自动反复重试。继续前先点击 **核对 / 更新主收藏**。

## 参数与隐私

参数保存在当前浏览器配置的同一 Tampermonkey 脚本条目中。更新时保留原条目。**清除本地扫描数据** 会清除快取、分类参数、名称映射和追加记录，保留语言偏好，不会删除 Pixiv 上的收藏。

项目 JSON 包含作品 PID、分类选择及原收藏标签，也可能涉及非公开收藏。请自行保管，提交公开 issue 前删去个人数据。导出不含账号 ID、Cookie 或 CSRF 凭据。当前没有跨浏览器 JSON 导入界面。

脚本没有外部运行依赖、统计上报或图片下载。请求在 Pixiv 同源会话内执行，写入凭据只存于内存。更多细节见 [实现说明](docs/DESIGN.md)。

## 验证与发布

Node.js 20 或更新版本下运行 `npm test`，无需安装 npm 依赖。附带测试使用模拟 DOM、网络、存储和虚构作品数据，覆盖语言切换、旧缓存恢复、分类计算、10 标签上限、保留原收藏、暂停、结果不确定及重复更新，不会请求或写入真实 Pixiv；没有模拟浏览器排版。

0.3.0 的追加流程已有用户实际运行并提供通过保留核对的完成记录。0.4.0 语言界面已完成本地验证；Pixiv 后续页面或内部接口变化仍可能需要适配。

`python3 scripts/package.py` 可重建安装 ZIP。参见 [更新记录](CHANGELOG.md) 和 [GitHub 发布说明](docs/RELEASING.zh-CN.md)。当前尚未指定分发许可证。
