# Pixiv ブックマーク分類ツール

[English](README.md) · 日本語 · [简体中文](README.zh-CN.md)

**ブックマーク全体から分類の組み合わせを自動で選び、どこまで網羅できたかを確認し、作品が増えても同じ分類を使い続けられます。**

コレクション内の元タグから、閲覧可能な全作品の網羅を目指して分類を選び、冗長な選択を除く Tampermonkey スクリプトです。書き込み前には、既存タグと新しい分類を合わせて各作品のタグ上限に収まるかを確認します。

**バージョン：0.4.0。** 日本語・英語・簡体字中国語に対応。初期設定はブラウザーの言語に合わせ、手動で選んだ言語も保存します。

## このツールの特徴

- **作るべき分類を全コレクションから選ぶ。** タグと作品の対応関係から集合被覆を計算し、冗長な分類を取り除きます。事前の辞書作成は不要です。頻度が低いタグも、取りこぼしを補うために必要なら残します。
- **取りこぼしを数値と一覧で確認する。** 作品ごとの網羅率、未分類の PID、1 作品あたりの最大分類数を表示します。手動選択の変更も即時反映します。分類間の重複を認め、その和集合で閲覧可能な全作品を網羅することを目指します。
- **実際に追加できるかを先に確認する。** 計画時は 1 作品あたり最大 10 分類に制限し、書き込み前に既存タグと新分類の合計が Pixiv の上限 10 個以内かを確認します。超過する作品はスキップし、既存タグを保持します。
- **追加した結果を再読み取りで検証する。** 総ブックマーク、既存タグ、公開設定を保持して新分類を追加します。最初の 1 件を検証してから残りを処理し、完了時にも確認します。作品ごとの実行記録を出力できます。
- **保存した分類を継続して更新する。** ルールと分類名の対応表を保存し、次回は不足分だけを追加します。外部の既存分類のメンバーを分類済みとして数え、残りを網羅する分類を計算することもできます。

中心となる特徴は **全体の網羅を計画 → タグの空き枠を確認 → 追加と再読み取り検証 → 保存したルールで更新** という一連の流れです。自動タグ付けやルールの保存は他のツールにもあります。今回確認した 3 件の公開説明には、分類集合の自動選択・冗長性の除去・未分類作品の明示的な確認を一体として行う機能の記載は見当たりませんでした。範囲と出典は [比較ノート](docs/COMPARISON.md) に記載しています。

分類数の大域的な最小性や、あらゆるデータでの 100% 網羅は保証しません。既存タグの空き枠は選択後に確認するため、プレビューで全件を網羅していても実際には追加できない作品が残る場合があります。未分類・スキップされた作品は明示します。

## インストール・更新

Web Locks に対応した新しいデスクトップ版 Chrome / Edge と [Tampermonkey](https://www.tampermonkey.net/) を想定しています。必要に応じてユーザースクリプトの実行と `www.pixiv.net` へのアクセスを許可してください。

1. [インストール用 ZIP](dist/pixiv-bookmark-analyzer-install.zip) をダウンロードし、Tampermonkey → ダッシュボード → ユーティリティ → ZIP インポートで取り込みます。
2. 旧版がある場合は、その項目を更新して保存データを保持します。更新として認識されない場合は、既存スクリプトのエディター内を[最新版のコード](pixiv-bookmark-analyzer-prototype.user.js)で全置換して保存してください。
3. Pixiv にログインし、自分のイラストブックマークページを再読み込みします。

更新時の互換性を保つため、基本スクリプト名は `Pixiv 收藏参数扫描器 · 只读原型` のままです。管理画面では日本語・英語の名前が表示される場合があります。0.4.0 はボタン操作後に分類タグを実際に追加します。インストール時のビルド作業は不要です。

## 最初の分類

1. 自動認識されない場合は自分のユーザー ID を数字で入力し、**開始・再開**を押します。公開・非公開のイラスト、漫画、うごイラのブックマークを読み取ります。小説は対象外です。
2. 完了後、**分類プレビューを開く**を押します。自動選択された分類を調整し、各分類の作品や未分類作品を確認できます。
3. **既存の分類を分類済みとして含めますか？** は初期設定ではオフです。オンにすると既存メンバーを分類済みとして数えます。外部の既存分類の名前の意味を推測したり、その分類に新しい作品を追加したりはしません。
4. **ブックマークを確認・更新**を押し、現在のブックマーク、既存タグ、分類名を読み取ります。追加可能件数、未処理件数、新しい名前を確認してください。この段階は読み取りのみです。
5. **追加開始**を押します。ボタンには対象件数が表示されます。最初の 1 件に追加して検証してから残りを処理し、完了時に結果を再読み取りします。

処理中はページを開いたままにし、別のタブでブックマーク、タグ、公開設定を変更しないでください。完了時の `pixiv-classification-project.json` は、分類設定・名前の対応表・実行ログのバックアップです。

## 分類の更新と言語設定

- **分類を更新**で保存済みルールを復元し、最新のブックマークを確認します。プレビュー確認後に追加してください。すでにルールを満たす作品には重複した書き込みを行いません。
- ルールを増やすと、新旧両方の一致する作品に分類を追加できます。選択解除したルールの過去の分類結果は保持し、今後の割り当てを停止します。
- メイン画面と分類画面の **表示言語** から、ブラウザーに合わせる・简体中文・日本語・English を選べます。画面が即座に切り替わり、未保存の選択や検索内容も保持します。
- 自動設定では、ブラウザーの優先順で最初に対応する言語を使います。中国語の地域別設定には簡体字中国語を表示し、対応言語がなければ英語を使います。
- 作品の元タグ、分類名、保存済みの対応表、初期接頭辞 `新_`、JSON のキー、診断コードは翻訳しません。

## 動作と制限

分類は Pixiv のブックマークタグで実現します。作品は複数の分類に属する場合があるため、分類の件数を足すと全体より多くなることがあります。網羅率は作品ごとに重複を除いて計算します。

ブックマーク、既存タグ、公開設定を保持し、タグの追加だけを行います。閲覧不可などのレコードは分類から除外し、総ブックマークには残します。[Pixiv の説明](https://www.pixiv.help/hc/ja/articles/235585488)では、1 件のイラストに付けられるブックマークタグは最大 10 個です。既存タグと新分類の合計が 10 個を超える作品は、その回の追加をすべてスキップします。

自動選択は元タグの完全一致で行い、網羅する作品を増やしてから冗長なタグを取り除きます。分類数の大域的な最小性は保証しません。完全一致の `R-18` と数値付き `users入り` タグは自動選択の対象外ですが、手動では選択できます。選んだルールに一致しない作品は未分類として残ります。

更新時も現在の状態を確認するため一覧をページ単位で読み取ります。差分処理となるのは書き込みです。通信エラー、結果を確認できない応答、レート制限では一時停止し、自動再試行は繰り返しません。再開前に **ブックマークを確認・更新** を押してください。

## 保存データとプライバシー

設定は同じブラウザープロファイル内の Tampermonkey スクリプトに保存します。更新時は既存項目を保持してください。**ローカルのスキャンデータを消去**すると、キャッシュ、ルール、分類名の対応表、追加ログが消えます。言語設定は保持し、Pixiv のブックマークは削除しません。

プロジェクト JSON には作品 ID、分類、元のブックマークタグが含まれ、非公開ブックマークの情報を含む場合もあります。公開 issue に添付する前に個人データを除いてください。アカウント ID、Cookie、CSRF トークンは出力しません。別ブラウザーへの JSON インポート画面は未実装です。

外部の実行時依存、利用状況の送信、画像のダウンロードはありません。通信はログイン済みの Pixiv 同一オリジンで行い、書き込み用の認証情報はメモリ内だけに保持します。[実装ノート](docs/DESIGN.md)も参照してください。

## 検証と開発

Node.js 20 以降で `npm test` を実行できます。npm 依存パッケージのインストールは不要です。テストは架空のデータと模擬 DOM・通信・保存領域を使い、言語切り替え、旧データの復元、網羅率、追加処理、タグ上限、中断、応答不明、再更新を確認します。実際の Pixiv への読み書きやブラウザーでの描画検証は行いません。

0.3.0 の追加処理はユーザーによる実環境での実行が完了し、既存データ保持の検証に合格した出力記録を確認済みです。0.4.0 の言語 UI はローカルで検証しています。今後の Pixiv のページ・内部 API の変更には追加対応が必要になる場合があります。

Python 3 の `python3 scripts/package.py` でインストール ZIP を再作成できます。[変更履歴](CHANGELOG.md)も参照してください。配布ライセンスはまだ選択していません。
